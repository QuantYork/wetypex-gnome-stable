# 实时语音输入与排查

当前方案使用实时语音组件，见下文“实时语音”及[成套部署说明](streaming-voice-setup.md)。前两节记录旧批处理助手的排查历史；已经安装实时版本时，不再运行旧的单行修复或通知补丁。

## 历史：录音识别成功但没有回填

本机排查发现：快捷键已触发、PipeWire 录音与 Opus 编码正常，识别返回成功，但含原始 UTF-8 中文的 `voice-inbox.json` 没有被当前适配层接收。使用不存在的会话编号分别测试原始 UTF-8 与等价 ASCII 转义 JSON：前者留在收件文件，后者被接收。未向任何应用投递测试文字。

最小兼容修复是将 `/usr/bin/fcitx5-wetypex-voice` 最后生成收件文件的 Python `json.dumps` 从 `ensure_ascii=False` 改为 `ensure_ascii=True`。中文内容不变，快捷键和麦克风设置不变。不把它解释为上游所有版本均有相同问题。

遇到相同症状才手动应用，需要管理员授权：

```sh
pkexec /usr/bin/python3 "$PWD/scripts/fix-voice-json.py"
```

脚本仅接受已知的唯一目标行，先把原脚本备份到 `/var/backups/wetypex-gnome-stable/`，再原子替换；遇到未知版本拒绝修改。正常安装器不会自动执行此系统级修复。WeTypeX 软件包更新可能覆盖它，更新后应先确认是否仍需该修复。

恢复时选择脚本打印的确切备份文件，使用管理员权限复制回 `/usr/bin/fcitx5-wetypex-voice`。这项系统脚本修复不属于用户目录卸载器管理的文件，卸载用户层方案不会自动撤销它。

验证：已用安装后的真实脚本处理合成识别结果，确认 JSON 等价且能被 Fcitx 接收。尚需用户在实际输入框中按住 Ctrl+Win 说话、松开并保持焦点等待，验证真实端到端回填。语音识别本身会使用 WeTypeX 上游联网功能，本项目不会额外上传录音或识别内容。

## 录音没有提示或感觉等待很久

当时安装的上游 helper 采用录完后编码、再上传识别的流程，不是边说边转写。本项目提供可选状态提示和不含内容的阶段耗时补丁：

```sh
python3 scripts/improve-voice-feedback.py --dry-run
python3 tests/test-voice-feedback.py
pkexec /usr/bin/python3 "$PWD/scripts/improve-voice-feedback.py"
```

补丁显示“正在录音”“正在识别”“识别完成、已准备回填”或失败通知，复用通知编号，不将录音内容、识别文本或账号信息放入通知。系统勿扰或通知设置可能影响可见性。完成提示意味着收件文件已写入，不保证焦点已切换的应用仍会接收结果。

同时在私有 `state/voice/latency.log` 中记录毫秒时间戳和阶段名：`record_requested`、`recorder_started`、`stop_requested`、`recorder_stopped`、`encoding_finished`、`recognition_attempt_N`、`recognition_finished`、`result_ready`。不写入录音或转写内容，每次新录音重置该耗时文件。保留原重试策略和音频编码参数，不为追求速度降低音质或关闭文字整理。

停止等待会把僵尸录音进程视为已经结束，避免在音频已关闭后仍因 `kill -0` 返回成功而空等。此改动不消除联网识别耗时，也没有实现流式识别。

应用前先备份到 `/var/backups/wetypex-gnome-stable/voice-before-feedback-<时间>.sh`。若要恢复，使用打印的确切文件覆盖 `/usr/bin/fcitx5-wetypex-voice`。这是独立系统级补丁，不由用户目录卸载器自动恢复，WeTypeX 升级可能覆盖它。脚本已带同一标记时重复执行不改动；未知布局拒绝修改。

验证使用模拟录音器、编码器、账户命令和通知工具，覆盖开始/识别/完成/失败、ASCII 收件格式和无内容耗时日志，不启动真实录音或访问网络。实际延迟改善仍需在用户下一次语音后按阶段记录确认。

## 实时语音与可修改的中间文字（实验版本）

已在 Fcitx 5.1.19、WeTypeX 2.2.3.657-10 上验证实时通路：PipeWire 原始 PCM → 持续 Opus 编码 → 同一识别会话内发送音频 → 更新 Fcitx 预编辑文字 → 结束轮询、确认最终结果后单次提交。临时文字带 `DontCommit` 标记，避免 Fcitx 在失去焦点时自动提交尚未确认的语音。输入框不支持行内预编辑时，使用输入面板显示临时文字。

`src/voice-supervisor.py` 负责唯一会话和子进程生命周期；`src/voice-stream-launcher.py` 保留现有账户锁、身份与 bwrap 沙箱；`src/voice-stream.hpp` 处理增量请求与结束轮询；`patches/wetypex-streaming-voice.patch` 修改原 WeTypeX host/插件。上游 WeTypeX 源码版权归 panxuc（MIT）；本仓库仅提供兼容层修改，不分发微信原引擎或账户数据。

行为：按住说话时持续替换当前预编辑全文，光标在末尾；松开后释放麦克风，等待最终润色后一次性上屏。Esc、切换焦点、关闭输入框或退出输入法会取消当前语音。等待最终结果时继续打字也会取消语音，避免迟到结果写进新的输入内容。当前单次录音上限约 10 分钟，结束轮询最多 12 秒；未得到确认的定稿时会保留最后文字并明确提示“最终润色未确认”。

配置位于 `~/.config/fcitx5/wetypex.json`：

```json
{
  "voice_streaming": true,
  "voice_smart_polish": true,
  "voice_punctuation": "添加完整标点"
}
```

这些字段应合并到现有配置，不能覆盖整份文件。`voice_streaming: false` 恢复录完后识别；完整恢复还需要还原插件和助手备份。不要把新版助手单独配给旧插件：旧插件会把每份中间快照当成正式提交，造成重复文字。

构建需要干净的 2.2.3.657-10 源码及匹配 Fcitx 5.1.19 的开发头文件。构建脚本在临时副本应用补丁，不修改原源码、不安装到系统：

```sh
python3 scripts/build-streaming-voice.py --source /path/to/fcitx5-wetypex-2.2.3.657 --out /path/to/staging
```

此实验尚未纳入普通安装器；系统插件和用户层组件必须成套安装并先备份，不能在未知版本直接覆盖。WeTypeX 软件包升级可能覆盖系统插件，应重新核对兼容性。

验证包括：合成语音通过真实接口逐步返回并修改前文，停止后返回包含完整句号/问号的确认结果；模拟设备测试覆盖释放、早停、取消、旧会话抑制；真实插件测试覆盖预编辑替换、末尾光标、重复定稿抑制、拼音核心重启和失焦取消。所有自动测试均未访问麦克风。安装后用户主动测试并确认：录音过程中已经出现文字，结束后可以定稿。其他应用仍需按实际使用检查。

实时模式不保存录音文件或转写日志，只在权限受限的收件文件暂存最新文字供插件读取；阶段耗时日志不含内容。识别使用原来的微信服务。连续识别期间仍持有原账户锁，同步任务可能等待本次语音完成。


## GNOME 顶栏录音状态

录音提示现放在输入法图标左侧的顶栏空白处，取代底部浮条。录音时显示绿色麦克风、“正在录音”和真实时长；停止后显示蓝色整理状态；按过回车时显示“定稿后发送”；完成短暂提示后隐藏。异常保持橙色警示，状态心跳丢失且录音仍在进行时不会假装已结束。

`wetypex-voice-indicator.service` 现在是轻量的 Gio 会话总线服务，复用已有 Python 状态模型，无 GTK 窗口、无焦点和鼠标遮挡。独立扩展 `wetypex-voice-status@quantyork.local` 每 250 毫秒异步读取无内容状态，放在 Kimpanel 图标左侧；无 Kimpanel 时尝试原生输入指示器。没有修改 Kimpanel 文件。GNOME 通常只在登录时发现新本地扩展，因此首次安装后需要重新登录一次。

状态文件与会话总线仅传递阶段、时间及进程身份，不含转写或录音；只在顶栏消费者活跃时更新就绪心跳。扩展未加载、停用或服务不可用时，原有通知作为回退。顶栏随 GNOME 顶栏显示策略工作，全屏隐藏顶栏时不另弹悬浮窗。

已安装配套实时组件的用户可执行：

```sh
python3 scripts/voice-panel.py
# 第一次安装后退出登录，再登录
# 恢复安装前的显示方式（本机为底部浮条）：
python3 scripts/voice-panel.py --restore
```

安装器校验 GNOME 50.1，先保存受管理文件及扩展开关的原始状态，不重启输入法或桌面，不改录音、识别或快捷键。备份和清单位于 `~/.local/state/wetypex-gnome-stable/`。恢复时保留安装后被手动修改的文件。此可选显示组件的恢复独立于普通候选框卸载器。

验证：隔离会话总线测试覆盖状态、真实计时、待发送、录音残留警示、消费者心跳及退出清理；GJS 测试覆盖显示文本与语法，未打开麦克风。原底部提示、Win+C 防误触和定稿后回车已由用户确认；新版顶栏的真实位置及录音显示仍待重新登录后确认。

### Win+C 等全局映射与语音修饰键

本机把 Win+C 映射成 Ctrl+C，同时把 Ctrl+Win 设为按住说话。输入法无法仅凭某个修饰键事件分辨它来自实体键还是映射恢复。修复增加 120 毫秒按住确认：在此之前释放修饰键、切换焦点或按普通键，均取消启动。确认期间的 Ctrl+C 不被消费。持续按住原录音键仍能启动；快速轻点不会打开麦克风。测试覆盖模拟的短暂组合键脉冲、Ctrl+C 透传、真正按住启动，以及已有语音回填保护。安装后用户实测确认：Win+C 复制正常，麦克风图标不再闪动。

### 整理期间按回车

录音或等待最终整理时按回车，会记住发送请求并等待定稿；最终文字正式提交后延迟 100 毫秒补发一次回车。重复按回车合并为一次请求，顶栏显示“定稿后发送”。Shift+Enter 保留换行含义；录音时的 Ctrl+Win 修饰键不会带到发送回车。识别失败、取消、切换输入框或开始另一段输入时取消待发送请求，避免误发。自动测试验证先提交最终文字再转发回车、重复按键合并及失焦取消。用户已在实际输入框测试并确认等待定稿后发送正常。
